Capital Data Wire applies this to the complete response. Its AI-written articles remain explicitly uncorroborated; no automated independent confirmation is claimed. ## Cloud migration plan and prelaunch checklist

1. Keep current authentication; use Supabase PostgreSQL as the data store, not an automatic Supabase Auth migration. Create a separate staging project only after approval. Apply existing migrations to staging, test backup/restore, session ownership, verification/reset, trial boundaries and subscription entitlements. Use transaction-pooler URLs for bounded serverless connections and the appropriate direct/session connection for migrations. Keep credentials server-only.
2. Replace loopback engine dependencies in production with shared durable snapshots/history and an authenticated bounded scheduled collector. Do not point Vercel to a home PC or try to run MT5 there. Retain local engine for tests until a licensed cloud ingestion path passes parity tests. No new production collector is activated by this change.
3. Add durable tables for instrument/provider contracts, capability-specific licence references, snapshots, source-specific OHLCV, session calendars and ingestion state. Unique observation keys must include instrument, provider and source time; bars include timeframe and venue/contract. Store bid/ask and explicit reference type separately. Never overwrite an actual trade timestamp with receipt time.
4. Implement PostgreSQL leases with owner UUID, expiry and atomic compare-and-set claim; renew for bounded runs and enforce fencing tokens on writes. Persist circuit state, Retry-After, exponential failure count, next attempt, global per-provider rate windows and discovery/history watermarks. Deduplicate scheduled invocations by provider/instrument/window. A failed run retains old data with stale/closed/unverified status; it never renews source time. Use transaction-scoped advisory locks or row leases, not in-memory Sets as cross-instance coordination.
5. Schedule minute HTTP batches only for supported active sessions. Validate licensed exchange holiday calendars, timezones/DST, early closes and futures maintenance/expiry/roll. One-minute schedules alone do not guarantee a sub-60-second freshness SLA; measure duration/jitter and choose a permitted cadence with margin. Crypto can keep its faster collector only on an appropriate authorised persistent or bounded cloud service. Website requests read central snapshots and never start upstream downloads.
6. For website updates, begin with cached bounded polling, private entitlement checks and explicit source age. If SSE/WS is used, use durable shared state/pubsub and bounded reconnections across instances. Vercel now documents WebSocket support, but process memory, function duration and invocation lifetime are not durable shared-engine guarantees. Benchmark database reads, connection pooling, fan-out and egress with representative authenticated load before pricing scale.
7. Separate calendar/news/SEC hourly collection from price work. Preserve primary-source URLs/licences, publication vs collection timestamps, cancellation/tentative status and corroboration flags. Add official release/company/exchange sources only after verifying their supported endpoints and terms. No independent high-impact confirmation is claimed by the current AI-written news source.
8. Configure production transactional email, verified sender, bounce handling and delivery monitoring. Finish business/privacy/retention/jurisdiction disclosures, backups, spending alerts, operational alerts, incident runbooks and audit retention. Keep billing in test mode through staging checkout/webhook replay, event ordering/reconciliation, past-due recovery and cancellation tests. No paying subscriber acceptance until approved rights and operational checks pass.
9. After staged approval, configure darktic.com DNS, TLS and server secrets; exercise production smoke checks and rollback. **Do not deploy from this checklist without approval.**
